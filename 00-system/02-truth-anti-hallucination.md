# 02 · TRUTH 体系：反幻觉规范

> 目标：让"AI 写的调研"和"人写的调研"都满足同一个标准——
> **每个事实可追溯、每个推算可复算、每个判断有署名、每个无知被记录。**

## 1. 四类陈述，四种标记（写作者义务）

| 类型 | 标记 | 定义 | 举例 |
|---|---|---|---|
| 事实 | `[S:编号]` 或 `[A1]`… | 有登记册/来源清单中的来源支撑 | "2025 年挖掘机出口 31.67 万台 [C24]" |
| 推算 | `[推算]` | 由两个以上事实经算术/逻辑导出，**必须附算式** | "22.85−10.06≈12.8 万台 [推算]" |
| 判断 | `[判断]` | 经验性结论，署名为写作者 | "先吃中资项目部客户 [判断]" |
| 待验证 | `[待验证]` | 查不到或只有一手弱来源，进入待验证清单 | "菲律宾贸易类外资实缴资本门槛 [待验证]" |

**红线**：文档里出现一个"裸数字"（无标记、无来源）= 违规，验证脚本会抽查。

## 2. 来源分层与 ID 方案

层级定义（与行业层 `05-source-list.md` 一致）：

| 字母 | 层级 | 可信度基线 |
|---|---|---|
| A | 官方法规/统计/部委/政府门户 | 高 |
| B | 行业协会、券商研报、律所、市场研究机构 | 中高 |
| C | 主流财经与行业媒体 | 中 |
| D | 从业者内容（货代、清关行、咨询、服务商博客） | 中低，须交叉 |
| E | 卖方/平台营销内容（出口商官网、B2B 挂牌） | 低，只看不信数字 |

ID = 字母 + 连续序号（A1, C24, E15…），全仓库唯一，登记在 `00-system/data/source-register.csv`。
**新来源先登记、后引用**；引用了不存在的 ID，验证脚本报错。

## 3. 采信规则（写进结论前逐条过）

1. 核心数字（规模、增速、价格、税费、机龄门槛）至少 **2 个独立来源**，其中至少 1 个 A/B 层；
2. 只有 D/E 层支撑的，只能写区间 + 标 `[E/L5 样本]`，并进待验证清单；
3. **口径对齐**：新机/二手、台数/金额、协会/海关、出厂/出口——引用时必须写明口径；
4. **时间戳**：每条来源记发布日期；政策类 >12 个月必须重查并更新"最后核验"；
5. **利益相关方识别**：卖方/服务商内容天然放大机会、淡化门槛，只作线索不作证据；
6. **反例检索**：每个"机会"结论配一次"为什么难做"检索，否则不成立。

```
---
```

## 5. 单一事实源（Single Source of Truth）

- 数字只"住"在一个地方：能进 `data/*.csv` 的进 csv，叙述文档**引用**而不复述；
- 必须复述时，复述处加来源 ID，且与 csv 一致；验证脚本对关键数字做抽查比对；
- 被推翻的结论不删除：移入 `90-archive/`，原位置留一行"已推翻→见 90-archive/xx，原因：…"。

## 6. 发布前验证门（Verification Gate）

提交前跑 `verify.py`（仓库根），任一项失败不得标记"已发布"：
1. 所有 md 有 frontmatter 且字段齐全；
2. 文中引用的 `[A-E]\d+` ID 全部存在于来源登记册；
3. README 与各文档的相对链接全部可解析；
4. 所有 csv 列宽一致、可被解析器读入；
5. 所有 `[推算]` 标记附近 3 行内出现算式（=、−、×、/、% 至少一个）；
6. 表格逐表竖线数一致。

## 7. 幻觉高危场景黑名单（本项目踩过或刻意避开的）

1. 把卖方博客当市场分析；2. 混用新机/二手口径；3. 只看机会不查反例；
4. 忽略时间戳（政策三年改三版）；5. 用区域平均值做单国决策；
6. **从记忆里引数字**——本会话不记得上一会话查过的数，必须重新检索或读登记册；
7. 把"平台挂牌价"当"成交价"（挂牌价天然虚高/虚低，只作区间端点）。

## 8. 出错时的动作

发现已发布文档有误：① 改正文；② frontmatter"最后核验"改当天；③ 在文档末尾"更正记录"表写一行
（日期 / 原值 / 新值 / 原因 / 来源 ID）；④ 若错因是方法缺陷，回到本文件补一条黑名单。
